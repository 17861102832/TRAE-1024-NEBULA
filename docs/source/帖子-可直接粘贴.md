## 一、先看它怎么演

整场观测由五个阶段串起来，每个阶段只做一件事：

```
BOOT → SCRAPING → WEAVING → CRUISING → INSPECTING
```

- **BOOT**：黑底辉光字 `NEBULA` 亮起，同时开始拉取数据（1~2 秒）；
- **SCRAPING**：左上角 `CRAWLER` 面板开始滚真实请求流水 —— 每一条都带时间戳、路径、状态码、耗时、字节数。**它不是在演，它真的在爬**；
- **WEAVING**：30 张 md 卡片在 Canvas 上被逐张生成贴图（标题栏 / 作者 / 正文摘要 / 外链数 / 角标），然后按力导向布局落进星群；
- **CRUISING**：相机自动向前航行（WASD 飞行 / QE 升降 / 拖拽转向 / 滚轮推拉），星尘从两侧掠过；
- **INSPECTING**：点任意一张卡，右侧抽屉展开完整正文 + 全部外链 + 论坛原帖；点空白处取消。

这里有个刻意设计：**爬虫流水不藏在设置页里，而是常驻在主视图上。** 因为这个作品唯一不可替代的东西就是"它真的在爬"——把它藏起来，等于把作品的灵魂锁进后台。

## 二、它爬了什么

| 通道 | 数据源 | 产出 |
| --- | --- | --- |
| 作品秀 | `forum.trae.cn/tag/109` + 案例与作品板块合并去重 | **30 个作品**（正文 / 外链 / 图片 / 回复全解析） |
| 盖楼 | 主帖 `post_stream.stream` 全量 id → `/t/{id}/posts.json?post_ids[]=` 批量取正文 | **593 层**，含每层作者 / 头像 / 点赞 / 时间 |
| 聚合 | 作者 + 楼层 + 回复交叉 | **368 位参与者** |

星云结构：**398 个节点 / 1335 条边**

- 人 ↔ 作品：作者归属边（带流动光点）
- 人 ↔ 人：盖楼射线 + 排队边（相邻楼层连一条弱边，看得出"排队"的形状）
- 作品 ↔ 人：评论边

其中 **25 人交了作品，343 人只盖楼**——这就是这届社区的真实形状：参与的人远多于产出的人，星云的密度差就是它自己。

> ⚠️ 一个容易踩的坑：`post_stream.posts` **只返回首批 20 条**，完整楼层 id 在 `post_stream.stream` 里。必须走 `/t/{id}/posts.json?post_ids[]=...` 批量端点才能拿全。我第一版只拿到 19 层，修正后才是 593 层。

## 三、RISK 是开关，不是仪表盘

这才是这个作品和"翻牌墙""纪念碑"的分界。

**仪表盘把数据摆出来给你看；观测台让你拿着指标去筛。**

右侧 `RISK` 四行都可以点。点下去的瞬间：

| 动作 | 星云里发生什么 |
| --- | --- |
| 命中 | 该作品节点**红色描边 + 放大 1.5× + 辉光转红 + 置顶渲染** |
| 其余 | 全部节点降暗到 **7%**（人物节点 9%） |
| 左下角 | `SELECT` 栏实时显示「**已筛选：无 Demo 链接 3 个**」 |
| 再点一次 | 200ms 缓动全部恢复 |
| 点另一行 | 直接切换筛选目标 |

## 五、TRAE 在这次创作里干了什么

这个作品最难的部分不是写代码，是**读懂两个陌生系统**。这一段全是 TRAE 的活。

**① 不猜 API，直接读打包产物**
`3d-force-graph` 的接口我连错了三次：导出不符 → `controlType` 不是方法 → `d3AlphaTarget` 不存在 → `d3Force('link')` 缺 `.id()` 把整个力引擎搞崩。
TRAE 直接去 `node_modules/3d-force-graph/dist/` 那个 4 MB 的打包文件里 grep `linkedFGProps` 白名单，**一次性把真实可用的方法列全**，从此不再猜。

**② 从源码挖出"为什么只有 1 fps"**
画面卡死、帧率显示 1。TRAE 顺着 `layoutTick()` 的停机条件一路挖到：

```js
if (++state.cntTicks > state.cooldownTicks
    || new Date() - state.startTickTime > state.cooldownTime
    || isD3Sim && state.d3AlphaMin > 0 && state.d3ForceLayout.alpha() < state.d3AlphaMin)
```

—— 原来这个库**本来设计就是"布局稳定就停渲染"**（`cooldownTime` 默认 15 秒）。改它才是正解，不是加补丁。

**③ 从雾参数算出"节点为什么全隐形"**
卡片画出来是黑的。TRAE 算出 `FogExp2` 在相机距离 620 时的雾因子 = `1 - exp(-(0.0105 × 620)²) ≈ 1.0` —— **全雾**。three 内置材质被吃干净，而自写 shader 的星星不吃雾，所以症状是"星星看得见、节点看不见"，极具误导性。

**④ 用对照实验区分"代码 bug"和"环境假象"**
无头浏览器测出来只有 1 fps。TRAE 分别测了 `requestAnimationFrame` 频率和 `renderer.render` 调用次数 —— **两个都是 1**，证明是无头 Chrome 没有合成器，而不是我的代码。换成有头浏览器一测，**公网真实 87~92 fps**。

**⑤ 把"能跑"推到"能看"**
md 卡片的 Canvas 动态贴图、5200 粒子的闪烁 shader、HUD 八个模块的霓虹配色、RISK 的 200ms 缓动高亮 —— 这些都是一版版截图对比调出来的。
